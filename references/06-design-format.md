# 06 · 设计类消息的排版（四套指纹）

这份管「八步协议」里给用户的消息怎么排。过校验器（check_message.py）的一律是纯文字版：加粗、表格是渲染环境的可选升级，不进校验。

出处：习惯引擎（habit-engine）03-format.md 的四套体系。核心判断是：同样一段话，用户必须扫一眼就分清「他在讲道理」「他在问我」「要我现在动手」。分不清，内容再对也会被读成一大坨，用户只会说「太长了」「不知道要干嘛」。

## 四套指纹

|套|是什么|指纹|用户该做什么|
|---|---|---|---|
|A 描述|报位置、接住、过渡、边界说明|裸段落，无符号无缩进|读|
|B 提问|要用户回答、要用户补库|引导句句末冒号，每条 · 开头，条间不空行|开口答|
|C 方法论|为什么这么设计|▍ 开头，紧跟「《书名》中的方法名」，独立成段|判断信不信|
|D 动作|用户当场要做的事|阿拉伯数字加整条【】括住，条间空行|起身做|

四套的区别是手指：A 不动，B 动嘴，C 动脑，D 起身。

序号分两层，不许撞车：

- 大写数字（一、二、三）只做架构层：应对卡卡头、红线清单这类内容块的标题。渲染环境下加粗。
- 阿拉伯数字（1、2、3）只做执行层：卡内或块内的条目编号。「要做」的动作整条加【】；「不能做」的禁止项不加【】，同属执行层。
两层撞了（卡头和卡内条目都用大写数字），架构就看不见了。

三条硬规矩：

一、提问一律圆点，动作一律方括号加阿拉伯数字。 中文数字加粗只出现在卡头。
二、一条消息最多一个 C 块。 C 块里不放问题、不放动作，语言换挡成书面第三方口吻，用「该原则指出」「对照本例」「因此」。
三、B 块上限三问，一条一问，问号结尾。

## 应对卡的三行格式（第 6 步专用）

第 6 步的每种反应固定三行，卡与卡之间空一行：

**N、类型词：她的反应**（原话形态，越像她本人越好）
你说：可直接说出口的那一句，不加修饰。
边界：这句话的止点在哪，多说一个字会坏在哪。

卡头两件套，缺一不可：类型词（两到四个字，写反应底下的本质，如挽留／指责／危机／试探／施压）加加粗的大写数字。不写类型词，五张卡长得一模一样，用户扫不出「现在进了哪种局面」；不加粗，卡头和下面的「你说：」混在一个字号里，架构沉底。类型词从 C 层的判断来（比如「五种反应是同一个不安全感的五种变形」），但只留词，不留论述。

「你说：」是话术的指纹，「边界：」是失效条件的指纹。两行都不许换成别的写法。

卡里若含用户当场要做的真动作（安全预案、报警、离场），动作单独成 D 块，不许塞进「你说：」那一行。

## C 块什么时候上

C 块（▍方法论）不是每步必上。判据一句话：用户此刻在等工具还是在问原理。

- 等工具（第 4、5、6、7 步）：不上。卡和清单本身就是交付，插一段道理反而拖节奏。
- 问原理（第 1、3 步，或用户质疑「为什么这么设计」）：上，且必须报书名。
第 6 步的类型词就是 C 块压缩后的残留：判断还在，论述拿掉。

## 设计类消息的默认结构

A  报步骤 + 一句话概括这一步只做一件事
A  一句过渡，交代位置（在框架的第几段、还剩什么）
A  内容引导句
   内容（应对卡／框架表／清单）
A  收一句
B  引导句冒号 + 扩充提问（第 6、7 步必须问）

C 块按上面「C 块什么时候上」的判据决定加不加，不进默认结构。

内容块本身用什么形态：应对卡用三行格式，框架用「阶段／时长／目的／核心一句」逐行排（渲染环境可用表格），材料清单用中文数字逐条排。

## 五条禁令

一、不许整段加粗。加粗是路标，不是喇叭。
二、不许提问用中文数字，不许提问加粗。加了，用户分不清你在问还是让他做。
三、不许一句话里混两套。应对卡里塞【】、提问里塞书名，都是混套。
四、不许用分隔线切段。一条消息切三段以上，说明该拆成两条消息。
五、不许在动作里埋条件。「有空的话」「尽量」一出现，这条动作就不存在了。

## 自检判据

写完一条设计类消息，扫一遍问三个问题：

· 哪些行是「问我」的？找不出 ·，就是问题埋进了散文。
· 哪些行是「要我动手」的？找不出【】，就是动作混进了描述。
· 道理为什么成立？找不出 ▍ 和书名，就是解释和话术糊在了一起。
